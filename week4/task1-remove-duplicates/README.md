# Remove Duplicates from Sorted List

## 1. Задача

Дан отсортированный связный список. Некоторые числа в нём повторяются.
Нужно удалить повторы, чтобы каждое число осталось только один раз,
и вернуть начало списка.

Например: 1 → 1 → 2 → 3 → 3 должно стать 1 → 2 → 3.

## 2. Решение

Так как список отсортирован, одинаковые числа всегда стоят рядом.
Поэтому достаточно сравнивать каждый узел со следующим.

Я завожу указатель cur и начинаю с первого узла.
Если следующий узел равен текущему, я его пропускаю: связываю cur
сразу с узлом через один. При этом cur остаётся на месте,
потому что новый следующий узел тоже может быть повтором.
Если числа разные, я просто иду дальше.
Цикл заканчивается, когда дохожу до конца списка.

```java
class Solution {
    public ListNode deleteDuplicates(ListNode head) {
        ListNode cur = head;
        while (cur != null && cur.next != null) {
            if (cur.val == cur.next.val) {
                cur.next = cur.next.next; // пропускаем повтор
            } else {
                cur = cur.next;
            }
        }
        return head;
    }
}
```

### Пример работы

Список: 1 → 1 → 2 → 3 → 3

- cur = 1, следующий тоже 1. Повтор, пропускаем его. Список: 1 → 2 → 3 → 3
- cur = 1, следующий 2. Разные, идём дальше.
- cur = 2, следующий 3. Разные, идём дальше.
- cur = 3, следующий тоже 3. Повтор, пропускаем. Список: 1 → 2 → 3
- cur = 3, следующего нет. Конец.

Ответ: 1 → 2 → 3

Ещё один пример, где три одинаковых числа подряд: 1 → 1 → 1 → 2

- cur = 1, следующий 1. Пропускаем. Список: 1 → 1 → 2
- cur всё ещё 1, следующий опять 1. Пропускаем. Список: 1 → 2
- cur = 1, следующий 2. Идём дальше.
- cur = 2, следующего нет. Конец.

Если список пустой, цикл не запускается и возвращается null.

### Трудности

Сначала я двигала cur вперёд после каждого сравнения.
На списке 1 - 1 -1 - 2 это не сработало: после удаления одного повтора
cur переходил на вторую единицу, и одна лишняя единица оставалась.
Я исправила это: теперь cur двигается только когда числа разные.

Ещё была ошибка NullPointerException. Сначала в условии цикла было
только cur != null, и на последнем узле cur.next.val вызывал ошибку,
потому что cur.next равен null. Я добавила проверку cur.next != null.

Я проверила решение на обычном списке, на трёх одинаковых числах подряд,
на списке без повторов, на списке из одного элемента и на пустом списке.

## 3 Сложность

Время: O(n), где n это количество узлов.
На каждом шаге цикла я либо удаляю один узел, либо сдвигаюсь на один узел.
Каждый узел обрабатывается один раз, поэтому шагов не больше n.

Память: O(1).
Я использую только одну переменную cur и не создаю новых узлов или списков.

## 4 Можно ли лучше

Быстрее чем O(n) сделать нельзя, потому что каждый узел нужно проверить
хотя бы один раз. Память уже минимальная, O(1).
Можно было бы написать решение через рекурсию, но тогда память стала бы O(n)
из-за стека вызовов, то есть хуже.
